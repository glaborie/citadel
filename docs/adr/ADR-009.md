# ADR-009: Bespoke HITL approval console

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

Temporal UI is an operator tool: it cannot render diffs, enforce four-eyes, capture signed reasons or TTL-auto-deny. Approvals are security decisions and need their own authenticated interface.

## Decision

1. Build a server-rendered approval console authenticated by Keycloak, with five views: run list, run timeline, pending approvals, approval detail and audit search.
2. Approval detail shows tool, canonical arguments, rendered diff, triggering policy rule, evidence/citations and TTL; approve/deny requires a reason.
3. Roles: requester, operator, approver, admin, auditor; an approver cannot approve their own request; T2 requires two distinct approvers.
4. TTL defaults to 15 minutes and auto-denies; audit event is written before the Temporal resume signal; programmatic approval API exists for tests.

## Consequences

- **Pros**: Human gates are usable, attributable and auditable; no approval authority in URL possession; good interview demo.
- **Cons**: A UI must be built and maintained rather than reusing Temporal UI.
