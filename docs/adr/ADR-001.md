# ADR-001: Clean-slate Citadel repository and scope

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

Two prior projects (a custom event-sourced harness and a security-heavy FastAPI/ARQ harness) overlap heavily with the target capability list and disagree on orchestration, audit and model clients. A third branch of that tree would inherit contradictions and produce documentation without a working demo.

## Decision

1. Create a new repository named Citadel; carry over lessons only, no source code or configs from prior projects.
2. Purpose: portfolio-grade reference architecture for senior AI-engineering roles, with real utility in the owner's homelab; no paying client.
3. Design phase is docs-only: README, architecture, ADRs, security/eval specs, milestones and an AGENTS.md handover. Implementation is delegated to OpenCode later.
4. Record explicit non-goals: no local GPU inference, no SaaS control plane, no billing, no general agent marketplace, no reversible DLP vault in v0.1.

## Consequences

- **Pros**: Clean boundaries and no inherited technical debt; a coherent story for interviews; scope small enough to actually finish.
- **Cons**: No reusable code means higher implementation cost; some hard-won details must be re-derived from the lessons report.
