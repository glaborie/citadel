# ADR-012: Hardened sidecar sandbox with gVisor upgrade path

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

Docker Sandboxes was investigated and rejected: login-gated, proprietary, host daemon outside Compose, 10-30 s startup, agent allowlist and local MCP servers running on the host. WASM cannot run arbitrary Python tools; RestrictedPython-style approaches are not security boundaries.

## Decision

1. Execute tools in an ephemeral sidecar container: no egress by default, cap_drop ALL, no-new-privileges, read-only rootfs, seccomp, pids/memory limits, per-invocation lifetime.
2. Never mount the Docker socket into a model-influenced component; use a restricted socket proxy only where strictly necessary and never for arbitrary tools.
3. gVisor runsc is the approved isolation upgrade: one runtime line in Compose, Apache-2.0, no nested virtualization, roughly 100-200 ms start.
4. Do not install or depend on docker sbx; it was uninstalled from the development host.

## Consequences

- **Pros**: Compose-native, fast, improvable isolation boundary without host hypervisor dependencies.
- **Cons**: Baseline sidecar shares the host kernel until gVisor is enabled; gVisor availability needs verification on the target host.
