# ADR-017: MLflow 3.x for trajectory evaluation

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

The stack must grade tool selection, argument accuracy, recovery and safety compliance, not final-text similarity. Evaluation results must be versioned and diffable over time.

## Decision

1. Use MLflow 3.x as trace store, dataset store, scorer harness and result UI; ingest spans via its native OTLP/HTTP endpoint.
2. Offline: pytest-style golden trajectories with deterministic assertions plus LLM/rubric judges; CI runs against pinned model and prompt-pack versions.
3. Online: sample real runs into the same store; run a lightweight scorer subset asynchronously.
4. Use custom scorers for Citadel-specific trajectory rules; built-in groundedness/relevance/safety scorers are supplementary.

## Consequences

- **Pros**: One tool for traces, datasets and comparison UI; full-span visibility; vendor-switchable via aliases.
- **Cons**: MLflow OSS auth is basic HTTP auth; Keycloak proxy required. Judge scoring needs its own budget and calibration.
