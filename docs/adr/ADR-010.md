    # ADR-010: Tool safety tiers and v0.1 allowlist

    **Status:** Accepted  
    **Date:** 2026-11-23  
    **Last modified:** 2026-11-23

    ## Context

    A DevOps agent with real homelab access needs an explicit blast-radius model. Unclassified or unreviewed capabilities must not be reachable by a model.

    ## Decision

    1. T0 read tools allowed by default with DLP, audit and sandbox controls.
2. T1 reversible writes require HITL approval; v0.1 allowlist is exactly restart_service and open_remediation_pr.
3. T2 destructive actions denied outright in v0.1; enable later only with four-eyes and per-call allowlists.
4. Unknown tools, missing tenant/run claims, unreachable policy service and unavailable DLP all deny.

    ## Consequences

    - **Pros**: Clear, explainable risk posture; small enough to test exhaustively; still useful in the homelab.
    - **Cons**: Limited capability in early milestones; every new tool requires classification and tests.
