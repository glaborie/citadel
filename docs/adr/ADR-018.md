    # ADR-018: Tenant-scoped cache and staged semantic routing

    **Status:** Accepted  
    **Date:** 2026-11-23  
    **Last modified:** 2026-11-23

    ## Context

    Semantic caches are a known cross-tenant leak and poisoning surface. The gateway's cache is not permission-aware. Routing must not send sensitive requests to a cheaper model by accident.

    ## Decision

    1. Implement caching in Citadel: exact match before semantic; partition key (tenant, entitlement_hash, agent, prompt_pack_version, model, tool_context_version).
2. Require TTL, calibrated similarity threshold, tenant/permission invalidation and gateway-only write path; cache no T1/T2 effects, approvals or credentials.
3. Add a red-team cross-tenant cache prompt test to the deployment gate.
4. v0.4 routing: deterministic intent match first, embedding route second, complexity escalation third; ambiguous or sensitive requests fail to the safer path.

    ## Consequences

    - **Pros**: Tail latency and token savings without cross-tenant reuse; routing is explainable and fail-safe.
    - **Cons**: Custom cache must be built and maintained; semantic threshold calibration needs labelled data.
