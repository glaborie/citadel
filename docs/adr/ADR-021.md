# ADR-021: MCP and A2A behind adapter seams

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

MCP is mature enough to consume; A2A has a real reference implementation but a thin ecosystem. Building directly against either would couple the runtime to protocol churn.

## Decision

1. Define a tool-source interface and an AgentConnector interface; implement adapters behind them.
2. Consume MCP tools in a later milestone with namespaced assembly; never expose OmniRoute admin MCP/A2A surfaces to agents.
3. Treat A2A as a seam only: no hard dependency, no protocol-specific policy logic in workers.
4. Replacing an adapter must require no changes to policy, workers or skill packs.

## Consequences

- **Pros**: Interoperability without lock-in; honest treatment of A2A maturity.
- **Cons**: Deferred interoperability means fewer out-of-box integrations in early milestones.
