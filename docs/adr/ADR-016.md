# ADR-016: Permission-aware Qdrant retrieval with rerank and citations

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

Generic vector search cannot express per-user ACLs, hybrid ranking or verifiable provenance. These must be designed into retrieval, not bolted onto results.

## Decision

1. Store runbook/inventory and selected GitHub documents in per-tenant Qdrant collections with content-hash revisions and ACL metadata.
2. Use named dense and server-side BM25 sparse vectors; derive allowed resource filter from OpenFGA and apply it inside the query before reranking.
3. Fuse with RRF, rerank top 50 to top 8 with a cross-encoder served by Text Embeddings Inference, then apply DLP redaction.
4. Require structured citations (source_uri, revision, chunk_id, line_range) and fail runs with unsupported operational claims.

## Consequences

- **Pros**: ACL leakage is prevented at the search boundary; answers are verifiable; hybrid retrieval improves runbook recall.
- **Cons**: Ingestion and provenance bookkeeping add complexity; hosted embeddings require egress controls.
