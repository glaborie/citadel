    # ADR-011: Skills as documentation, never authority

    **Status:** Accepted  
    **Date:** 2026-11-23  
    **Last modified:** 2026-11-23

    ## Context

    The user wants each specialist to carry relevant SKILL.md packs with progressive disclosure. Without a hard boundary, a skill file becomes a privilege-escalation vector.

    ## Decision

    1. Each specialist owns a version-controlled skills directory with an index and optional references; full text loads only when relevant.
2. Skill packs are hash-pinned in the specialist manifest; no dynamic install, URL fetch or auto-update.
3. Skills cannot declare tools, broaden allowlists, bypass DLP or override policy; permissions remain in OpenFGA and tool manifests.
4. User-supplied skills require review and version bump; skill pack version appears in traces, audit and eval fixtures.

    ## Consequences

    - **Pros**: Familiar, modular agent behaviour with a clear security boundary; easy to show in a portfolio.
    - **Cons**: Skill packs need curation and hash discipline; prose cannot encode enforcement.
