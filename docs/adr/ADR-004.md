    # ADR-004: OpenFGA as the single authorisation store

    **Status:** Accepted  
    **Date:** 2026-11-23  
    **Last modified:** 2026-11-23

    ## Context

    Keycloak roles cannot express resource- and argument-level tool policy, and permission-aware retrieval needs the same decision set. Two separate systems would drift and produce a leaky RAG.

    ## Decision

    1. Deploy OpenFGA as the one ReBAC/policy store for tool authorisation and retrieval ACL filtering.
2. Every tool call passes through one authorize() chokepoint with subject, agent, tool, canonical arguments, tenant and risk tier.
3. Policy models live in versioned repo files with unit tests; deny on unknown tool, missing tenant or policy-service failure.
4. Skills are documentation only and cannot declare or widen permissions.

    ## Consequences

    - **Pros**: One source of truth for policy; same relations power tool gates and search filters; testable policy-as-code.
    - **Cons**: Requires Zanzibar-style modelling discipline; another service in Compose.
