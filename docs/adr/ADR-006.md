# ADR-006: OmniRoute constrained to provider routing

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

OmniRoute advertises semantic cache, credential masking, prompt-injection guards, 5-second request idempotency and MCP/A2A control surfaces. These are not tenant/entitlement-aware and must not be mistaken for Citadel controls.

## Decision

1. OmniRoute owns provider abstraction, model aliases, tier routing, fallback, quotas and cost headers only.
2. Disable its semantic cache and treat its idempotency window as unrelated to durable tool idempotency; Citadel implements both controls.
3. Do not expose OmniRoute's admin MCP/A2A interfaces to agents; bind dashboard to an internal network behind a Keycloak OAuth2 proxy.
4. Pin an exact upstream repository and image commit at implementation time; GitHub redirects and many forks were observed during research.

## Consequences

- **Pros**: One egress path for credentials, cost and routing without conflating gateway features with security controls.
- **Cons**: Custom cache and idempotency must be built; exact upstream verification is an open implementation task.
