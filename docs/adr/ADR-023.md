# ADR-023: Pre-approved command allowlist, executed without a shell

**Status:** Proposed
**Date:** 2026-11-23
**Last modified:** 2026-11-23

## Context

The specialists need their own CLIs: `docker` for the Docker specialist, `gh`
for the GitHub specialist. Two settled constraints collide with the naive
answer of installing the CLIs in the worker containers.

- Ground rule 6 / ADR-012: never mount the Docker socket into a
  model-influenced component. A worker running a model loop is exactly that.
- The `internal` network has no egress, so `gh` cannot reach `api.github.com`
  from a worker, and giving workers egress breaks the property that only
  OmniRoute leaves the box.

An endpoint-level proxy alone is too blunt: enabling `POST` on a Docker socket
proxy also enables container create, exec and delete. A free-form CLI is too
wide: `gh api` reaches anything the token allows. The owner's direction is
correct — **a pre-approved command list**, tight but useful.

## Decision

1. CLIs run **only** inside the tool runner. No worker container gets the
   docker socket, the `gh` binary or network egress.
2. Execution is governed by a versioned **command allowlist**
   (`citadel/tools/commands.json`). Each entry names the binary, the required
   argv prefix, the closed set of permitted flags, and how many positional
   arguments may follow. Anything not matched is denied — including unknown
   flags, extra positionals and an unlisted binary.
3. Commands are exec'd as an **argv list with `shell=False`**. No shell, no
   pipes, no redirection, no metacharacters. Any token containing `;`, `|`,
   `&`, `$`, backticks, `<`, `>` or a newline is rejected outright, so a
   command cannot chain a second action.
4. Default deny is enforced before transport. The allowlist is the primary
   control; a proxy is defence in depth, not the authorisation.
5. T0 commands run through a **read-only** Docker socket proxy (list, inspect,
   logs, compose ps/config). T1 `docker compose restart` is executed by a
   narrow operator service holding the write path, never by the sandbox, so no
   model-influenced component can reach a writing endpoint.
6. `gh` uses a fine-grained PAT scoped to the entitled repositories, with
   egress allowlisted to `api.github.com`. `gh api` is **not** allowlisted: it
   is a general-purpose escape hatch and defeats the list.
7. Every execution emits an audit event with the matched allowlist id, the
   canonical argv and the decision that authorised it.

## Consequences

- **Pros**: The blast radius is a finite list a reviewer can read in one
  screen; denying a capability is a one-line diff, not a new proxy
  configuration; shell-free exec removes an entire class of injection; the
  matched command id is a natural audit key and eval assertion.
- **Cons**: "Variations" means the list will grow and needs curation; a flag
  with surprising semantics can still be dangerous (`--since` on logs is
  benign, but the pattern repeats), so new entries need review rather than a
  rubber stamp. The T1 operator service remains an extra component.

  **The allowlist constrains actions, not content.** Two allowlisted T0
  commands disclose secrets by design: `docker inspect` dumps
  `.Config.Env`, and `docker compose config` prints the fully interpolated
  file, including values that came from `.env`. Neither is safe to expose to
  a model until the DLP wrapper is in place. Until then they must run only
  with redaction applied to their output, or stay unregistered in the tool
  catalog even though the command allowlist permits them.
