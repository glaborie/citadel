# ADR-023: CLI access from the sandbox, never from a worker

**Status:** Proposed
**Date:** 2026-11-23
**Last modified:** 2026-11-23

## Context

The specialists need their own CLIs: Docker for the Docker specialist, `gh`
for the GitHub specialist. Two settled constraints collide with the naive
answer of installing the CLIs in the worker containers.

- Ground rule 6 / ADR-012: never mount the Docker socket into a
  model-influenced component. A worker running a model loop is exactly that.
- The `internal` network has no egress, so `gh` cannot reach `api.github.com`
  from a worker, and giving the worker egress weakens the property that only
  OmniRoute leaves the box.

ADR-012 already permits "a restricted socket proxy only where strictly
necessary and never for arbitrary tools", but does not say which endpoints.

## Decision

1. CLIs run **only** inside the tool runner. No worker container gets the
   docker socket, the `gh` binary or network egress.
2. Docker reads for T0 (`inspect_containers`, `read_logs`,
   `get_service_health`) go through a read-only socket proxy attached to the
   tool runner. The proxy exposes container listing, inspection and logs and
   nothing else.
3. T1 `restart_service` is **not** routed through the proxy. It is executed by
   a small privileged operator service that accepts only an
   `(tenant, run_id, container, action)` tuple together with a signed approval
   token minted by the API after the Temporal decision. The model-influenced
   path stays read-only; the only writer is a component that never sees model
   output.
4. The GitHub specialist reaches GitHub through an allowlisted egress path to
   `api.github.com` with a least-privilege token, scoped to the repositories
   the tenant is entitled to.
5. The tool runner keeps `cap_drop: ALL`, `no-new-privileges`, a read-only
   rootfs and a per-invocation lifetime. Proxy attachment is per invocation, not
   persistent.

## Consequences

- **Pros**: The socket never enters a model-influenced component; T1 writes
  have a single narrow writer with an auditable interface; the read and write
  paths are visibly different.
- **Cons**: One more service to build and operate, and the tool runner loses
  `network_mode: none` when a proxy is attached, so its isolation story becomes
  "no egress except a specific proxy" rather than "no network". The approval
  token becomes a security-critical object and must be short-lived and
  single-use.
