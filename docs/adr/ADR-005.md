    # ADR-005: Multi-tenancy enforced from the first line of code

    **Status:** Accepted  
    **Date:** 2026-11-23  
    **Last modified:** 2026-11-23

    ## Context

    Initial tenant count is one, but retrofitting tenant isolation is exactly how cross-tenant leaks are introduced. Retrieval, cache and audit all inherit this decision.

    ## Decision

    1. Every run requires a tenant claim from a verified token; no request parameter can supply it.
2. Postgres uses RLS keyed on the tenant claim; Qdrant uses per-tenant collections (small tenant count); cache partitions include tenant and entitlement hash.
3. Audit ledger is hash-chained per tenant; eval fixtures and traces carry tenant IDs with redacted payloads.
4. Red-team tests attempt cross-tenant reads through API, retrieval, tool and cache surfaces.

    ## Consequences

    - **Pros**: Isolation is structural, not a later migration; strong demonstration value in a portfolio piece.
    - **Cons**: Per-tenant collections and RLS add overhead even with one tenant.
