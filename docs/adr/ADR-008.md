# ADR-008: Four-milestone evolution roadmap

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-25

## Context

A 16-feature stack cannot be delivered as one undifferentiated release. Each milestone needs a demonstrable exit test and explicit non-goals.

## Decision

1. v0.1: secure vertical slice — auth, tenant, policy, gateway, guarded read, HITL-gated write, audit, one trace and one golden trajectory.
2. v0.2: permission-aware RAG, Researcher specialist, SOPS+age secrets, offline eval suite.
3. v0.3: online grading, model comparisons, tenant-scoped cache, Prometheus metrics.
4. v0.4: MCP consume adapter, A2A seam, sandbox-only code mode, semantic routing.
5. Record non-goals per milestone; reconcile this roadmap with delivered scope before closing each one.

## Consequences

- **Pros**: Every milestone is demo-able and testable; scope creep has a named home.
- **Cons**: Later features are deliberately deferred, which may require explanation to reviewers.

## v0.1 reconciliation (2026-11-25)

Full review: `docs/exit-review-v0.1.md`.

| Listed for v0.1 | Delivered |
|---|---|
| Auth, tenant, delegated run token | yes — Keycloak 26 user token verified against JWKS; the API mints an Ed25519 run token carrying user, tenant, agent, scopes, tier and run ID (ADR-003 decision 3 exercised) |
| Policy chokepoint, RLS, audit | yes — OpenFGA `authorize()`, forced RLS, hash-chained per-tenant ledger; chain verified |
| **Gateway** | **partly** — `OmniRouteClient` and the bounded agent loop exist and are exercised by tests and four red-team cases, but no workflow calls them, so no run sends a model request. Carried into v0.2 as the first open item |
| Guarded read, HITL-gated write | yes — three T0 reads, `restart_service` and `open_remediation_pr` as T1, all T2 denied |
| One trace, one golden trajectory | yes — one T1 trace with policy, DLP, approval and tool spans sharing a run id and matching audit rows |
| Skill packs, versioned | yes as content, hashes, loader and checked provenance; consumption depends on the gateway row |

Scope that moved **into** v0.1: the approval console (ADR-009) was built, not
sketched; the red-team pack grew to 29 cases; four v0.2/v0.3/v0.4 attack surfaces
(`RT-INJ-05`, `RT-DLP-05`, `RT-COST-01`, `RT-EVAL-01`) were exercised early and
pass.

Scope that moved **out** of v0.1, recorded rather than dropped: browser-grade
MLflow authentication (only needed if the UI is published), judge-scored rubrics,
and the retrieval ACL surface that `RT-AUTHZ-01` originally named. Everything
else listed for v0.2 to v0.4 is untouched and stays where it was.
