# ADR-015: Separate audit ledger from traces and Temporal history

**Status:** Accepted  
**Date:** 2026-11-23  
**Last modified:** 2026-11-23

## Context

Traces answer debugging questions; audit events answer accountability questions. Temporal history is internal. Mixing them produces three overlapping event streams that disagree.

## Decision

1. Emit one structured security event at each chokepoint into an append-only Postgres table, SHA-256 hash-chained per tenant.
2. Export OTel spans to MLflow OTLP/HTTP /v1/traces with an audit event ID attribute on relevant spans.
3. Temporal history remains internal only; Prometheus metrics are optional service-level telemetry.
4. Audit never auto-expires; trace retention is 90 days; MLflow is fronted by a Keycloak OAuth2 proxy on an internal network.

## Consequences

- **Pros**: Clear separation of concerns with cross-references; tamper-evident security evidence; one eval/trace UI.
- **Cons**: Two persistence pipelines must be kept consistent; MLflow OSS auth is basic auth, not native Keycloak SSO.
