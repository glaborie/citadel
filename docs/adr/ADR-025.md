# ADR-025: Hosted embedding may see DLP-redacted text; reranking stays in-stack

**Status:** Accepted
**Date:** 2026-11-26
**Last modified:** 2026-11-26

## Context

`AGENTS.md` verification item 5 and #136 asked whether hosted embedding and
reranker endpoints may see Citadel data. The owner answered on #136
(comment 7191249151): hosted embedding and reranker may see redacted data.
The retrieval path needs a dense embedding endpoint, and ADR-016 already names
OmniRoute as the hosting layer and TEI as the reranker.

The sensitive question is not "may a provider see bytes" but "which bytes, and
what happens when the guard or the endpoint fails". A chunk body can contain a
credential, PII, or a runbook path that identifies the homelab. The audit
ledger and traces must keep citation metadata, never the body.

## Decision

1. **What leaves the host.** Only text that has passed the `output` DLP surface:
   PII is irreversibly redacted, and a credential blocks the whole ingestion or
   query. This applies to chunk text before it is embedded and to query text
   before it is embedded. Chunk bodies are stored in Qdrant as written; they are
   not sent to the hosted endpoint unredacted.
2. **Where it goes.** Embeddings go through OmniRoute's OpenAI-compatible
   `/v1/embeddings`; the model is `CITADEL_EMBEDDING_MODEL`, an alias the
   deployment configures. Workers never call a provider endpoint directly.
   The API key is a Docker secret (`OMNIROUTE_API_KEY_FILE`); `.env.example`
   carries only the empty alias and the in-stack reranker URL.
3. **Reranking does not leave the host.** The cross-encoder is TEI in Compose
   (`reranker`, digest-pinned). Reranker input is the already-redacted chunk
   text. A future hosted reranker would need its own decision; this ADR does not
   authorise it.
4. **Retention.** Citadel retains no copy of what it sends beyond its own
   Qdrant points and audit metadata. Retention at the embedding provider is
   governed by the upstream provider's terms, reached through OmniRoute; it is
   not a Citadel control and is accepted as part of this decision. Audit and
   trace records keep hashes, ids, URIs, revisions and scores, never the body.
5. **Failure mode is refusal.** A DLP detector that is unavailable or blocks, an
   embedding endpoint that is unreachable or returns malformed vectors, and a
   reranker that is unreachable or returns an out-of-range index all raise or
   return a refusal. There is no sparse-only fallback: a result the hybrid path
   did not produce is not a result the citation schema can describe.

## Consequences

- **Pros**: Hybrid retrieval exists without sending unredacted runbooks to a
  provider; the turn-off switch is configuration, not code; reranking has no
  egress at all; failures are visible as refusals rather than silent degradation.
- **Cons**: Ingestion now depends on Presidio and the embedding endpoint, so an
  unavailable detector or alias blocks a knowledge refresh; provider-side
  retention is outside the audit chain; redaction can change embeddings for
  chunks that contain PII.
