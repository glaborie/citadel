# Issue #180/#181 — Citadel answer cache

Implementation note for ADR-018 decisions 1–3. No settled decision changed; this
records the choices the ADR left to implementation.

## What caches what

- The cache stores a **text answer only**, keyed by the digest of the exact
  message list and by the ADR partition key.
- Only the **first step** of a task run is cacheable (`history` is empty).
  With no history the answer cannot contain a tool result, so a T1/T2 effect,
  an approval or a credential-bearing tool output has no path into the table.
- A reply that requests a tool is not stored; a reply refused by the output DLP
  gate is not stored. A hit is re-gated before it is served, so a poisoned row
  cannot skip the detector.
- Semantic lookup runs only on the first step and only inside one partition.
  Candidates from another embedding model are ignored, because their vectors
  are not comparable.

## Partition components

| Component | Source |
|---|---|
| tenant | the verified run token's tenant |
| entitlement_hash | digest of the submitter's Keycloak roles at `POST /runs` |
| agent | the run's specialist |
| prompt_pack_version | the assembled pack id (`docker-1.0.0`) |
| model | the requested OmniRoute alias |
| tool_context_version | sha256 of `citadel/policy/tools.json` |
| policy_version | sha256 of `policy/model.json` (the model OpenFGA loads) |

`policy_version` and `tool_context_version` are computed from the versioned
files, not hand-bumped, so a policy or allowlist change rotates the partition
without a deploy step that someone can forget. The path candidates cover the
repository and `/app/policy` in the image; if neither is readable the key is
refused and the cache is skipped.

`invalidate_tenant` deletes a tenant's rows. Entitlement and policy changes
invalidate by key rotation, which is stronger than a delete job: the old rows
are unreachable before any cleanup runs.

## Failure behaviour

A store or embedder failure is a **miss**, never a served entry. The model call
then runs with every control intact. The red-team executors fail the case if the
cache cannot be constructed or exercised, so an unavailable cache cannot be
mistaken for a passing isolation proof.

## TTL and threshold

- `CITADEL_CACHE_TTL_SECONDS` defaults to 3600. Every row carries `expires_at`,
  and no query returns an expired row. Physical deletion of expired rows is not
  scheduled: it needs an owner-level connection because RLS scopes every app
  connection to one tenant. Expired rows take space, never a request.
- `CITADEL_CACHE_SIMILARITY` defaults to 0.95, deliberately conservative. A
  false hit answers a different question; a miss costs one model call.
  `citadel.cache.calibrate_threshold` picks the midpoint between the weakest
  true pair and the strongest false pair and refuses overlapping sets. Real
  calibration waits for a labelled paraphrase set; the default is not claimed to
  be calibrated against one.

## Evidence

- `tests/test_cache.py`: partition completeness, TTL, tenant invalidation,
  semantic threshold and embedding-model boundary, unavailable store/embedder.
- `tests/test_model_step.py`: exact hit skips the second model call, tool
  requests and DLP-refused answers are never stored, later steps do not read it.
- `RT-CACHE-01`: cross-tenant exact and semantic lookups miss; the probe
  embedder returns one vector for every text, so only the partition can stop it.
- `RT-CACHE-02`: a policy-model or tool-catalog change misses while the old key
  still hits.
